## 第一篇：产品首发（优先发布）

标题：改英文论文，最怕“这不是我想说的”

备选：
- 中文想明白了，英文又卡住了
- AI把英文润色好了，我却不敢用了
- 做了个工具：改中文，英文跟着改

封面主标题：英文很顺，意思跑了？
封面副标题：先改中文，再看英文怎么变
封面演示沿用局部 diff；示例注明“原创功能演示”。

正文：

“这句英文看着挺专业，但我想表达的好像不是这个意思。”

改论文时，这一步很容易卡住：
中文知道要怎么改，换成英文又得斟酌一遍；交给 AI 润色，拿回来还要逐句对照它改了什么。

所以我做了纸桥 PaperBridge，把这几步放到同一个界面里。

比如把这句：
“我们的方法彻底消除了幻觉”
改成：
“我们的方法在测试集上减少了幻觉”。

直接改右侧的中文，模型会回写对应英文。
左侧保留没变的部分，标出删掉的 eliminates、新增的 reduces 和 on the test set。

我想要的是：中文里把意思说清楚，英文里把变化看明白。

📄 导入英文 Word，左右对照阅读
✏️ 修改中文译文，回写对应英文
🔎 查看改动，核对后再导出 Word

已经开源，项目名 PaperBridge，GitHub 搜索 jkjkiiiii/PaperBridge。
目前需要自行配置 API 或本地模型，Word 原生版面在 Windows＋Microsoft Word 环境验证。模型生成的英文仍需要自己检查。

你改英文论文时，更容易卡在“怎么表达”，还是“AI改完不放心”？

## 第二篇：开发者实测

标题：给论文做中英句子对应，花了多少钱？
备选：这次DeepSeek映射账单：约1毛2
封面：约 ¥0.12 / 这次中英句子映射花了多少

正文：

做论文工具，除了“能不能用”，我还想把“到底花多少”算清楚。

这次拿 Attention Is All You Need 做了一个样本：从论文源码重建 Word，用火山机器翻译生成中文，再让 DeepSeek Flash 建立中英句子的对应关系。

跑下来的记录：

• 火山初译：27,490 字符
• DeepSeek 映射：98,982 tokens
• DeepSeek 控制台消费：约 ¥0.12
• 顺序运行：约 5 分 51 秒
• 40 条参考文献及标题跳过翻译和映射

为什么还要做句子对应？
因为后面改中文时，需要知道该改哪部分英文。翻译只是这个流程的第一步。

这 1 毛 2 是本次 DeepSeek 映射的消费，不是所有论文的统一价格，也不含之后改中文触发的英文回写。火山费用取决于账号剩余额度；两段映射修复另外约 ¥0.0029。

工具已经开源，叫 PaperBridge。完整用量记录和测试范围放在项目里，想自己算成本的可以参考。

## 第三篇：功能答疑

标题：翻译用火山，改英文能换DeepSeek吗？
封面：翻译 / 句子对应 / 英文回写，分别选

正文：

可以，这三步可以分别配置。

用 PaperBridge 时：

① 初始翻译：先把英文文稿翻成中文，可以选专用翻译 API，也可以选 LLM。
② 句子对应：让 LLM 建立中英文对应关系，后续编辑才知道要回写哪里。
③ 英文回写：修改中文后，由这里选的 LLM 生成对应英文变化。

比如这次实测用火山做初译、DeepSeek 做句子映射。也提供 LM Studio 本地模型接入。

专用翻译适配包括火山、DeepL API、Azure Translator 和自托管 LibreTranslate；通用模型适配包括 DeepSeek、OpenAI、Anthropic、Gemini、Kimi 开放平台等。

具体能选哪些模型，要看自己的账号和接口支持情况。云端请求会发给所选服务；API 费用也由对应服务计算。

设置入口和操作截图放在图里。项目名 PaperBridge，已经开源。
