# PaperBridge 发布与传播计划

## 定位与宣传场景

**产品口号：改中文，同步改英文论文。**

**主宣传标题：导师：这句话，说得太满了。**

原创功能演示围绕一次具体修改：中文译文从「我们的方法彻底解决了模型幻觉。」直接编辑为「我们的方法在测试集上减少了模型幻觉。」；对应英文从 “Our method eliminates hallucinations.” 回写为 “Our method reduces hallucinations on the test set.” 作者再对照 diff 检查英文变化。这是为展示操作编写的例句，不是论文结论，也不表示工具能自动判断证据、纠错或审稿。

PaperBridge 面向希望掌握论文修改过程的研究者，提供中英对照阅读、直接编辑中文译文和人工核对英文变化的工作流。GitHub 面向愿意配置环境和模型的使用者与贡献者；小红书用故事和真实界面展示流程；朋友圈讲论文修改体验并邀请反馈。

## 七天试行排期

| 日 | 动作 | 观察与下一步 |
| --- | --- | --- |
| 1 | 整理 GitHub 首屏、快速开始和截图 | 记录访问、克隆或下载及问题基线 |
| 2 | 发布小红书六图与正文，给出项目入口 | 记录曝光、主页访问、收藏和评论，收集理解障碍 |
| 3 | 整理反馈，邀请研究者用合适的文稿试用 | 记录安装、导入和首次导出情况及失败原因 |
| 4 | 发朋友圈，讲导师反馈后的修改场景 | 记录主动询问与反馈，了解是否理解产品用途 |
| 5 | 根据反馈补充真实 diff 演示或成本案例 | 记录关于修改范围、准确性和费用的疑问 |
| 6 | 修正文档或制作安装说明 | 复测首次使用流程并记录阻塞点 |
| 7 | 汇总数据与定性意见，决定下一轮内容 | 列出最常见的三个问题，观察从访问到实际使用的情况 |

节奏和指标是试验设计，不代表平台分发规律或效果承诺。不可得的数据标记为不可得；样本较少时优先看具体反馈和阻塞原因。比较标题或首图时，尽量一次只改一项并记录日期与样本规模。
