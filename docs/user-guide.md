# PaperBridge 使用指南

## 1. 选择模型

在左侧打开 **模型与术语设置**。任务分配页可为翻译并对齐、局部英文回写、对齐修复分别选模型。

### 云端服务

选择 Kimi、Anthropic、OpenAI 或 Google 标签，表单会使用对应官方地址、认证方式和协议。通过“获取密钥”链接打开官方控制台，填写自己的 API Key。读取账号模型列表后选择模型，或填写服务提供的准确模型 ID。

切换厂商使用独立配置草稿，保存后才加入模型列表；模型发现不会隐式保存整个配置。已保存密钥不回传浏览器，显隐按钮只显示本次输入。官方地址和协议的自定义入口位于高级设置。

### LM Studio 或自定义服务

1. 在模型服务中加载模型并启动 API。
2. 选择 **其他**，使用 LM Studio 预设或自定义服务。
3. 填写 API 基础路径，例如 `http://127.0.0.1:1234/v1`；模型 ID 以服务实际返回为准。
4. 按服务能力选择协议及结构化输出模式。
5. 保存并测试所选模型。测试使用内置短句，不发送文稿。

附加参数只适用于当前配置，不要把某个 Qwen 模型的参数直接复制给其他厂商。“请求上下文预算”用于工具预检，不会修改 LM Studio 实际加载的上下文长度。

### Kimi 的平台区别

中国站与国际站开放平台分别使用对应地址和密钥。会员 Coding 服务的额度、凭据及适用范围与开放平台不同；后台批量翻译使用开放平台。会员信息页不代表已登录或可以使用订阅额度执行批处理。依据见 [厂商适配说明](provider-adaptation.md)。

## 2. 导入与翻译

导入 `.docx` 后，工具保存原始文件副本，并为段落、句子与保护对象建立索引。含未接受 Word 修订的文件会被拒绝；先在另一份副本中处理修订，再导入。

点击 **翻译未处理段落**，按段落生成译文和句子对应关系，结合术语与相邻上下文。普通表格保留行列及合并单元格；纯数字单元格原样对应，不经模型改写。

术语页可以输入 `English = 中文`，或导入 CSV（`en,zh` 两列）及 JSON：

```json
[
  { "en": "self-attention", "zh": "自注意力" },
  { "en": "encoder", "zh": "编码器" }
]
```

术语设置影响后续请求，不能证明既有译文已经符合新术语。

## 3. 两种阅读视图

### Word 原生版面

页面来自本机 Word 对工作副本的排版输出，图片、公式、表格和页眉页脚作为真实内容显示。中英文可以有不同的行数与页数。

点击可定位的文字，在中文段落位置打开纯文字编辑框。编辑期间保留页面位置，避免重新排版打断输入；完成回写并收起编辑框后显示更新页面。跨页段落可以在续页片段处编辑。

无法可靠定位时，仍可在原生视图内的“位置未匹配”浮动框修改；这只是编辑入口，不表示程序知道精确坐标。模型未完成回写时，页面显示最近已同步内容，并列出待处理段落。草稿不会被当成已经同步的英文结果。

### 结构编辑

连续显示正文和完整表格，适合检查逐句差异、修改单元格及人工修复映射。保护对象可能显示为 `⟦P000⟧` 等内部标记，不能更改、删除或重排。它们在 Word 导出中仍对应原对象。

页眉页脚、脚注尾注和文本框当前只读保留。带保护对象、分节符或位于表格内的段落不能直接删除。

### 对应颜色与对齐

悬停句子时，两侧对应文字联动高亮；开启“全部对应着色”可持续显示对应组。必要的 1:N、N:1、N:M 对应共享组色，不强行拆成一一对应。

鼠标停留在一侧段落约 120 毫秒后，只移动对侧对应段落到相同阅读高度。编辑、选字和输入法组词期间暂停联动。结构视图支持段内多句拖选；原生页面不提供完整 Word 文本光标或页面逐字拖选。

## 4. 中文修改与英文回写

右侧修改会保留草稿。开启自动回写时，停止输入后调用模型；关闭后可先编辑草稿，再手动回写。

回写只允许受影响的英文句子变化，其他句子需保持原样。新的英文、中文和映射一起提交，旧请求不能覆盖新修改。差异视图以初始英文和初始译文为基准显示增删。

普通段内编辑不跨段落，换行或跨段粘贴不能暗中新增结构。新增／删除正文段落使用显式段落按钮。

混合格式替换有时无法唯一决定新文字的样式来源，此时选择继承左侧或右侧格式。文字变长可能正常改变换行、行高及分页。

## 5. 换模型与全文重译

更换模型不会覆盖已有译文。点击 **重新翻译全文** 后：

1. 检查当前修改是否已同步。
2. 以当前英文生成独立重译版本，保留已完成的英文编辑。
3. 固定任务开始时的模型、术语与配置，重建普通段落译文和映射，不复用旧翻译缓存。
4. 保留原项目及其编辑记录。

进度区显示模型、完成数量和失败数。暂停在当前请求结束后停止后续处理；继续会重试未完成及失败段落。任务在后台运行，关闭网页不会停止；服务重启后标为中断，可继续处理。

## 6. 保存、导出与恢复

**保存项目 JSON** 包含项目状态、草稿和最终有效补丁。**导出 Word** 生成已同步的英文副本；有待回写、冲突或失效映射时，需先处理。

对同一原文件导入 JSON 时，程序检查哈希、原文前置条件、结构与保护对象，再提供合并预览。重复导入不会重复插入内容；重叠修改、失效锚点和结构冲突会报告冲突。

原文件版本不同，只在普通文本段落有唯一精确匹配时迁移，不按段落编号猜测定位。导出项目不带 API 密钥，跨设备恢复后需重新配置凭据。

## 7. 常见问题

| 情况 | 处理方式 |
| --- | --- |
| Word 页面不可用 | 确认 Windows 中可启动 Microsoft Word；暂时切换结构编辑，草稿仍保留 |
| 模型连接失败 | 检查地址、端口、服务启动状态及 API Key |
| 等待生成超时 | 先检查模型是否仍在生成；工具不自动重复提交读超时请求，避免叠加排队 |
| 模型列表为空 | 使用服务实际提供的模型 ID；检查账号权限和厂商平台是否匹配 |
| JSON 输出失败 | 检查结构化模式及输出预算；失败结果不会覆盖已同步版本 |
| 待对齐或映射歧义 | 打开对应关系修复，或指定允许修改的英文范围后重试 |
| 页面仍是旧内容 | 查看版本提示；完成回写、收起编辑框后等待页面更新 |

## 8. 本地数据

```text
.data/
  settings.json          模型、任务路由及术语设置
  secrets.json           本机密钥
  projects/<id>/
    original.docx        原始文件副本
    project.json         译文、草稿、映射和编辑记录
  cache/                 模型输出缓存
  previews/              Word 排版中间结果
  native-pages/          页面图片和坐标缓存
```

这些目录不应提交到公开仓库。项目 JSON、缓存和日志可能包含论文内容；使用云端模型时，相关文字会发送到所选服务。模型生成与格式工程验证不能替代人工学术校对。

## 英文差异的显示粒度

英文默认按完整单词展示增删，例如`entirely → solely`显示删除整个entirely并新增整个solely。仅明确识别的常见时态／词形变化细化到词内，例如`work → worked`只标新增ed；不能确认词形关系时保守使用整词。连字符复合词、撇号缩写及数字作为整体；空白和标点变化仍准确保留。中文保持字符范围diff。这是显示层规则，不修改句子映射、JSON补丁范围或Word导出方式。

实现复用[jsdiff](https://github.com/kpdecker/jsdiff)的词元序列比较；[diff-match-patch](https://github.com/google/diff-match-patch)的语义清理与词边界思路可供参考，但并不自行识别英语语法变化。本工具不为显示diff额外调用模型。

## 独立翻译 API 与 DeepSeek

在“翻译服务”和“通用模型”管理连接、凭据与测试；在“任务分配”统一选择初始翻译引擎、句子映射模型和英文回写模型。新增DeepSeek独立标签。配置步骤、免费条件与降级规则见[翻译服务说明](translation-services.md)。

## 参考文献自动跳过

导入或打开文档时，依据独立的 References／Bibliography／参考文献标题及文献样式识别参考文献区。该区保留英文，不调用翻译或句子映射模型，也不显示双语句子颜色。正文中的引文标号不会因此被跳过；参考文献后的 Appendix 等新章节恢复正常翻译。

结构编辑中会显示“参考文献 · 保留英文”。识别有误可点击“纳入翻译”；普通段落也可手动点击“跳过参考文献”。旧项目已有的译文和编辑记录会保留，避免自动识别覆盖用户修改。标题不规范的文献可能漏检，请结合标记人工检查。

实测 token 与人民币费用的口径、账本格式见[费用核算说明](token-cost.md)。
